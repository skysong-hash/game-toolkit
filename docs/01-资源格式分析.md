# 资源格式分析

记录游戏资源包结构的分析方法与通用思路。

## 1. 常见打包格式

多数游戏客户端使用自定义的归档格式，典型结构：

```
┌─────────────────┐
│  Magic (4B)     │  文件标识
├─────────────────┤
│  Version (4B)   │  格式版本
├─────────────────┤
│  EntryCount(4B) │  条目数量
├─────────────────┤
│  IndexTable     │  索引表（每项固定长度）
├─────────────────┤
│  DataBlocks     │  数据块（可能压缩/加密）
└─────────────────┘
```

## 2. 索引表结构

索引表每项通常包含：

| 字段 | 类型 | 说明 |
|---|---|---|
| offset | uint32 | 数据块在文件中的偏移 |
| size | uint32 | 数据块大小 |
| nameHash | uint32 | 资源名哈希 |
| flags | uint16 | 压缩/加密标志 |

## 3. 哈希算法识别

资源名通常不直接存储，而是存哈希。常见哈希：

- CRC32
- FNV-1a
- 自定义多项式哈希

**识别方法**：拿已知资源名计算各算法哈希，与索引表中值比对。

```js
function crc32(str) {
  let c, crc = 0xFFFFFFFF;
  for (let i = 0; i < str.length; i++) {
    c = (crc ^ str.charCodeAt(i)) & 0xFF;
    for (let k = 0; k < 8; k++) {
      c = c & 1 ? 0xEDB88320 ^ (c >>> 1) : c >>> 1;
    }
    crc = (crc >>> 8) ^ c;
  }
  return (crc ^ 0xFFFFFFFF) >>> 0;
}
```

## 4. 压缩与加密

### 压缩

常见：zlib / lz4 / zstd。判断方法：

- zlib: 头两字节 `78 9C` / `78 DA`
- lz4: 头四字节 `04 22 4D 18`
- zstd: 头四字节 `28 B5 2F FD`

### 加密

简单异或加密最常见：

```js
function xorDecrypt(buf, key) {
  const out = Buffer.alloc(buf.length);
  for (let i = 0; i < buf.length; i++) {
    out[i] = buf[i] ^ key[i % key.length];
  }
  return out;
}
```

密钥通常硬编码在客户端代码中，可通过字符串搜索或动态调试定位。

## 5. 分析流程建议

1. 用十六进制编辑器观察文件头，识别 Magic
2. 找重复出现的固定长度结构 → 定位索引表
3. 用已知资源名反推哈希算法
4. 检查数据块头部 → 判断是否压缩
5. 若压缩，尝试标准解压；失败则考虑加密

## 6. 工具推荐

- `010 Editor` — 模板化解析二进制格式
- `ImHex` — 开源十六进制编辑器，支持自定义模式语言
- `binwalk` — 自动识别嵌套格式
