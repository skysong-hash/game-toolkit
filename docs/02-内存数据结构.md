# 内存数据结构分析

记录运行时数据结构的分析方法（只读分析，不修改目标进程）。

## 1. 分析流程

```
定位模块 → 找基址 → 追踪指针链 → 确定结构体布局 → 验证字段含义
```

## 2. 定位模块基址

Windows 下枚举进程模块：

```js
import ffi from 'ffi-napi';

const kernel32 = ffi.Library('kernel32', {
  GetModuleHandleA: ['pointer', ['string']],
});

const base = kernel32.GetModuleHandleA('game.exe');
console.log('模块基址:', base);
```

Linux 下读 `/proc/<pid>/maps`：

```
00400000-00452000 r-xp 00000000 08:02 1234  /path/to/game
```

第一列起始地址即基址。

## 3. 指针链追踪

游戏对象通常通过多级指针访问：

```
[base + 0x1A2B3C] → +0x10 → +0x28 → 玩家对象
```

**手动追踪步骤**：
1. 用 CE（Cheat Engine）找到某字段的地址
2. 做"指针扫描"（Pointer Scan），限定层数
3. 验证重启后地址是否稳定

## 4. 结构体布局推断

同一对象内字段通常连续排列，规律：

- 数值字段按 4/8 字节对齐
- 字符串多为指针 + 长度（std::string）或定长数组（char[32]）
- 容器（vector/map）内部有 3-4 个指针

**验证方法**：观察字段随游戏行为的变化

| 观察到的现象 | 推断 |
|---|---|
| 值在 0~100 间跳变 | 可能是百分比/血量 |
| 值单调递增 | 可能是经验/金币 |
| 值变化时界面同步刷新 | 确认是关键字段 |

## 5. 只读分析的安全边界

本项目只做**只读**分析：

- ✅ 读取内存、解析结构、可视化数据
- ❌ 不写入内存、不修改游戏状态、不绕过任何校验

只读操作不改变目标进程行为，风险最低。

## 6. 常用工具

| 工具 | 用途 |
|---|---|
| Cheat Engine | 内存搜索、指针扫描 |
| x64dbg | 动态调试 |
| IDA / Ghidra | 静态反汇编 |
| ReClass.NET | 结构体布局可视化 |
